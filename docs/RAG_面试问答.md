# RAG 设计与评测：阶段问答笔记

这份笔记整理我们在项目设计阶段已经讨论的问题。答案是可用于面试表达的简洁版本；后续实验会补充本项目的实测数据。当前项目设计见 [DESIGN.md](../DESIGN.md)。

## 1. 从上传 PDF 到回答问题，RAG 经历哪些步骤？

**答：**分为离线建库和在线问答。离线阶段提取 PDF 文本及版面结构，清理内容，按标题或语义切块，生成索引并保存来源位置。在线阶段根据问题检索候选证据，排序和筛选后将证据送给模型，生成带引用的回答。

**关键点：**PDF 解析与切块不一定需要大模型。表格、标题、页码和代码块如果在解析时丢失，后面的检索很难补救。不同资料源应使用不同解析适配器；本项目的 CrewAI 场景首先处理 Markdown/HTML 文档。

## 2. 正确答案在资料里，但系统答错了，怎么定位？

**答：**沿链路检查：原文是否被正确解析和切块；正确证据是否进入索引；检索是否找到；找到后排名是否足够靠前；它是否进入模型上下文；模型是否正确使用证据并给出恰当引用。资料本身存在冲突或版本不一致时，还要先确定哪份来源有效。

**关键点：**“模型幻觉”是可能的原因，但不能在没有检索记录时直接下结论。一次请求至少保存问题、策略及索引版本、全部候选、候选排名、实际送入上下文的证据、回答和引用。

## 3. 检索返回五个块，正确证据排第四；为什么要记录全部候选和实际上下文？

**答：**五个块都要记录，重点检查第四块。如果系统只送前三块给模型，那么检索已经找到了证据，但排序或上下文截取使它无法用于回答。如果第四块已经送入模型却仍答错，排查重点转向上下文组织和生成。只保存最终回答无法区分这两类失败。

**面试追问：**Recall@5 可能合格，但正确证据仍没有进入只取前三块的上下文。因此还要检查实际上下文覆盖率，以及最终引用能否支持回答。

## 4. 第四块同时出现问题中的 A 和 B，为什么不能仅凭词出现就把它排第一？

**答：**同时出现 A、B 是有用的相关性信号，但该块可能只是目录、举例或无关列表。另一个块即使没有原样出现 B，也可能用别名或上下文真正解释两者区别。排序应判断证据能否回答整个问题，并结合标题、语义、关键词、来源范围和必要的重排。

**关键点：**检索目标是找到能够支撑答案的证据，不只是找到包含查询词的文本。

## 5. 改变切块方式后 Recall@5 从 72% 升到 85%，能直接证明新方案更好吗？

**答：**不能。先确认使用了相同的文档版本、问题集、证据标注、检索模型和其他配置，主要变化只有切块方式。还要考虑块变大可能让 Recall@5 更容易上升，却占用更多上下文，带来更高成本，甚至降低答案质量。应同时比较证据进入上下文的比例、引用正确性、回答质量、延迟及 token 用量，并查看逐题得失。

**关键点：**不同切块方案的块 ID 和粒度不同，评测标签应锚定原文位置；比较时还应控制相同的上下文 token 预算。

## 6. 为什么评测证据不能只标记向量库里的块 ID？

**答：**块 ID 只在某次切块和索引构建下稳定。原文内容更新、切块大小变化或分割边界变化，都可能改变块 ID；即使原文没变，也会发生。正确证据应标记到固定来源版本、文件、章节及必要的原文范围，再映射到当前实验的块。内容哈希可帮助检测资料是否发生变化。

**本项目做法：**CrewAI 场景固定上游 Git 提交和文档版本，评测题目前标注到文件与章节。后续加入更精确的原文范围，以支持切块方案之间的严格对比。

## 7. 中文提问、英文文档，为什么关键词检索可能失败？

**答：**BM25 主要依据查询词与文档词的重合度。中文的“层级流程”与英文的 “hierarchical process” 表达同一概念，却没有可匹配的词。可用人工或模型翻译查询作为关键词基线，也可用支持跨语言的向量模型；两者都需在同一题集上测试，不能假设向量一定更好。

**本项目做法：**CLI 接受显式英文 `--search-query`，同时提供 E5 跨语言向量检索。两种输入分别评测，避免把中文查询失败误判为切块失败。

## 8. 模型输出了 `[1]`，能认为引用正确吗？

**答：**只能先检查 `[1]` 是否对应实际送入上下文的证据。即使编号有效，证据也可能与断言无关或只支持其中一部分。要进一步按断言检查来源片段是否真正蕴含该断言，并特别注意无答案问题与来源冲突。

**本项目做法：**`citation_numbers_valid` 只做编号完整性检查；后续人工抽样和答案评测才判断语义支持关系。

## 9. 正确证据排第 8，但只给模型前 3 块，怎么解决？

**答：**先确认正确段落已被解析、入库，并出现在候选第 8 位。这说明候选召回成功，但排序与上下文筛选没把证据送给模型；不能直接归因于生成模型幻觉。查看前 7 块是否只是反复提到问题中的概念，却没有回答完整问题，再检查正确块的标题、措辞和切块边界。

**改进顺序：**用关键词与跨语言向量检索扩大候选范围并去重；在候选集合上重排，优先选择能够支撑完整答案的段落；若正确内容被切断，再调整切块；若查询含糊，再尝试查询改写。重排只能调整已召回的候选，不能找回候选集合中不存在的证据。直接增加送入模型的块数可能增加成本与干扰，不能代替定位排序问题。

**如何验证：**固定文档版本、问题集和上下文预算，比较候选 Recall@10、最终上下文命中率（例如 Context Hit@3）、逐题排名、回答证据支持度、延迟与 token 用量。特别记录“Recall@10 命中但 Context Hit@3 失败”的题，判断新策略是否真正改善了这个故障。

**本项目做法：**请求日志保存全部候选与实际送入模型的块 ID；C02 的长表切块调整后，正确证据从混合检索第 9 位进入前 3。后续仍需验证更多题，特别是 C04 的多证据覆盖。

## 10. 向量检索让 Recall@10 上升，为什么 Context Hit@3 可能不变？

**答：**向量检索可能把更多正确证据带进候选前 10，但它们仍排在第 4 到第 10 位，未进入生成上下文。要逐题比较排名、实际选择的块和干扰块，而不是只看候选召回率。可尝试重排或融合检索信号，并在相同上下文预算下验证；增大候选数量本身不等于改善最终答案。

**本项目实验 1：**CrewAI 17 道可回答题中，BM25 人工英文查询的全证据 Recall@10 为 12/17、Context Hit@3 为 10/17；E5 中文原题分别为 14/17、10/17。混合检索达到 16/17、11/17，但有单题退步。表格切块后的实验 2 数据见 [检索实验报告](../reports/README.md)。

## 11. 为什么把长表格拆小后，一道题答对了，整体 Recall@10 却下降？

**答：**切块改变了检索单位。短块让某些字段的语义更集中，也减少向量输入截断；但相关信息若分散在多个新块中，多证据问题可能更难在固定 Top K 内集齐。BM25 的文档长度归一化和向量相似度也会随块内容变化。因此要重新建索引，在同一题集、Top K 与上下文预算下同时比较总体指标和逐题得失。

**本项目实测：**按表格行分组后，C02 的正确证据在混合检索中从第 9 位升到第 3 位，真实问答得到有出处的正确解释；但 C04 的两处标注证据未在前 10 集齐。混合检索全证据 Recall@10 从 16/17 降到 15/17，Context Hit@3 从 11/17 升到 12/17。不能只展示变好的那道题，下一步需分析多证据题与答案质量。

## 12. 比较题找不齐两边证据，为什么不直接把上下文从 3 块增到 20 块？

**答：**更长的上下文可能覆盖遗漏的证据，但同时混入更多无关或片面的段落，增加模型混淆、token 成本和延迟；若某一侧证据根本不在候选中，扩大上下文也找不回来。先看每一侧证据的候选排名，再考虑把问题拆成多个检索意图，分别召回并检查覆盖。扩大上下文可以作为受控对照实验，不能代替召回与排序诊断。

**本项目实测：**C04 的 Agent 证据在中文 E5 第 19 位，Task 证据第 4 位，原 RRF 前 10 没集齐。人工拆成 Agent、Task 两个中文子问题并轮流取候选后，两处标注证据都进入前 3。但 6 道比较题中 C14 仍退步，说明简单轮流取候选也不是通用答案；人工子问题的效果不能当作自动拆题效果。

## 13. 已经拆成两个子问题，为什么仍可能找不齐两边证据？

**答：**“拆成两问”只改变输入，并不保证两次检索找到不同方面的证据。如果两个子问题措辞相近，或跨语言模型把区别性的词映射得不够准确，两路候选可能高度重复。轮流取候选和去重只能保证给每路留位置，不能纠正每路内部的错误排名。需要查看每个子问题的原始候选、重叠程度及缺失证据的排名，再测试查询改写或针对意图的重排。

**本项目实测：**C14 两条中文子问题都将“类级持久化”排第 1；去重后“方法级持久化”排第 4。把第二问改成明确的英文 `Method-Level Persistence` 表述后，它在该路升到第 1。这只是错误定位，不能直接作为自动改写能力或正式评测成绩。

## 14. 自动拆出的两个问题看起来合理，为什么正式评测反而更差？

**答：**拆题文本通顺不等于每一路都能检索到正确证据。查询中的关键区别可能没有被跨语言向量模型充分区分，多个子问题也可能召回相同干扰块。应先固定拆题提示词和测试题，再对照原题向量与混合检索，逐题检查每一路候选、最终上下文和标注证据；同时记录额外的 API 用量。不能只凭少数已调过的题宣布改进。

**本项目实测：**6 道新比较题中，人工拆题在旧题上的提升没有延续到自动拆题。DeepSeek 自动拆题使全部标注证据进入前 3 的题数只有 1/6，中文原题 E5 为 2/6，原混合检索为 3/6；拆题额外用了 1841 tokens。这是检索证据覆盖的负面结果，尚未测答案质量。

## 复习提示

遇到 RAG 答错的问题，先问三件事：**证据在原文吗？证据进上下文了吗？回答真正受证据支持吗？**这分别对应资料处理、检索与生成三个层次。

# PDF 输入适配：下一阶段的边界与验收

当前骨架已能切换固定 Markdown/MDX 场景并导入本地 Markdown/MDX，但尚未处理 PDF。原始目标中的“PDF 阅读、语义分割、知识块入库”因此还未完成。先以**可复制文本的 PDF**为第一种输入；扫描版 PDF 需要 OCR 和版面质量评估，不能把空文本页静默当作成功导入。

## 骨架接口

资料适配器应产出统一的块字段：内容、文档内容哈希、来源文件名、页码或页范围、页内顺序、标题路径、解析器版本与可点击原 PDF 的页码链接。Markdown/MDX 仍使用文件行号；PDF 使用页码，界面和引用不能把页码显示为 `L1–L1`。原 PDF、抽取文本、规范化块与索引应按资料版本一起保存，替换文件时建立新快照。

处理顺序：验证文件大小与 PDF 格式 → 按页抽取文本 → 记录每页文字量与异常 → 清理重复页眉页脚和断行 → 按标题/段落切块，长段落再切 → 生成带页码的块 ID → 写入现有 BM25/E5 索引 → 通过原 PDF 页码回看证据。模型辅助切分只能在保留原页码映射的基础上运行；不能让模型改写原文后再把改写内容当作可引用证据。

## 验收用例

1. 两页以上的文本型 PDF：跨页不丢字，同页两个段落可分别检索，引用打开正确页。
2. 表格、代码或双栏页：抽取顺序人工核验；错误顺序应有可见提示或拒绝导入，不伪装为可信知识块。
3. 扫描页：识别为“文本不足，需 OCR”，不能得到空知识库却显示导入成功。
4. 同名 PDF 替换：旧索引不混入新问答；请求记录仍可追到旧版本。
5. 至少一组有页码标注的问题：分别评测页码召回、最终上下文覆盖、答案要点和引用支持；PDF 的检索成绩不能直接套用 Markdown 题集。

当前环境尚未安装 PDF 解析 Python 包，也没有用于上述版面验收的代表性 PDF。接入时先确定解析库与依赖安装方式，再用可公开提交的样本验证；私有 PDF 仅留本地并由 Git 忽略。

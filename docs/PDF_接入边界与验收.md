# PDF 输入适配：下一阶段的边界与验收

当前骨架已接入**可复制文本的 PDF**：在本地场景上传原文件，按页提取并建立同一套 BM25/E5 索引，回答引用能跳到原 PDF 页码。扫描版 PDF 仍需要 OCR 和版面质量评估；模型辅助语义切分尚未实现。明确区分“输入适配已能跑通”和“复杂 PDF 解析质量已验证”。

## 骨架接口

6B 已验证两份真实文本 PDF。可选 `ordered_tables` 模式把有框表格的字段关系写入独立索引，引用仍跳转原 PDF 页码。实际答题改善集中在表格题。未覆盖无框表和扫描件，复杂版面需抽查。[6B 实验与启用方式](../reports/STAGE6B_PDF_LAYOUT.md)

资料适配器产出统一的块字段：内容、版本化块 ID、来源文件名、页码、标题路径与可点击原 PDF 的页码链接。Markdown/MDX 仍使用文件行号；PDF 使用页码，界面和生成提示词显示第 N 页。原 PDF 与索引按资料版本保存，替换文件时建立新快照。当前没有单独持久化完整抽取文本；索引中保存了每块正文，可重新从原 PDF 抽取。

当前处理顺序：验证 8 MB、200 页上限和 PDF 格式 → `pypdf` 按页抽取 → 标记文字不足的页 → 按页内空行与 1800 字符目标切块 → 生成带页码的块 ID → 写入现有 BM25/E5 索引 → 通过 `#page=N` 回看原 PDF。每块都只来自一页；尚未自动清理页眉页脚、识别标题或修复双栏顺序。未来模型辅助切分必须保留原页码映射，不能把改写内容当作可引用原文。

## 验收用例

1. 两页以上的文本型 PDF：内容不跨页混合；检索与回答引用指向正确页。两页合成 PDF 的 HTTP 上传、检索、原文下载和真实 DeepSeek 回答已通过，见[端到端测试记录](../reports/PDF_SMOKE_TEST.json)。
2. 表格、代码或双栏页：抽取顺序人工核验；错误顺序应有可见提示或拒绝导入，不伪装为可信知识块。
3. 扫描页：整份文字不足时拒绝导入；部分页文字不足时显示页码警告，不为该空页伪造证据。已用无文本页测试；真正扫描图像和 OCR 仍待验收。
4. 同名 PDF 替换：新索引只含新内容，旧原 PDF 和索引保留。已用两版合成 PDF 测试；历史请求记录仍需在实际用户上传后复核。
5. 至少一组有页码标注的问题：分别评测页码召回、最终上下文覆盖、答案要点和引用支持；PDF 的检索成绩不能直接套用 Markdown 题集。

安装：`.\.venv\Scripts\python.exe -m pip install -r requirements-pdf.txt`。本轮完成 24 项单元测试，其中 4 项覆盖 PDF 解析、页码、拒绝空文本和替换；另以两页合成 PDF 完成一次 HTTP + DeepSeek 真实回答。后来已在两份文本 PDF 上验收双栏与有框表格，真实扫描件仍待验收。私有 PDF 只留本地并由 Git 忽略。

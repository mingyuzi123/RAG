# 本地文档替换实验：资料版本、索引与块 ID

实验日期：2026-11-02。实验资料为仓库中的两份虚构多 Agent 工作流说明：[v1](../examples/learning/v1/agent_workflow.md) 和 [v2](../examples/learning/v2/agent_workflow.md)。它们具有相同文件名，只有“失败重试”段落中的次数从 2 改为 4。通过页面在“我的本地文档”场景先导入 v1，再勾选替换导入 v2；两次都用 E5 检索“每个子任务最多重试几次”，候选 Top K 为 10、回答上下文 K 为 3，并真实调用 DeepSeek。

| 核对项 | v1 | v2 |
| --- | --- | --- |
| 当前资料版本前缀 | `cd9057391ff1` | `f33d625826bc` |
| 活跃 BM25 索引 | `bm25-60bf23d80308.db` | `bm25-18833b3606a5.db` |
| “失败重试”块 ID | `21fc0e3062dbe4e7c91a` | `35a45f2de67ae53d49a8` |
| 内容未改的“执行记录”块 ID | `7c668956fc432a6581ef` | `73248bc4aa017434934f` |
| E5 排名第一的证据 | 最多重试 2 次 | 最多重试 4 次 |
| DeepSeek 回答 | 2 次，引用 `[1]` | 4 次，引用 `[1]` |

两版各切出 4 块。v2 检索返回的全部 4 块均来自新文件，没有出现旧版的“2 次”；旧文件和两个版本的 BM25/E5 索引仍保留在本机。替换后，manifest 只列当前文件，`index_path` 根据 manifest 内容版本得到新路径，因此正常检索只查当前索引。这个实验验证了本次替换流程，不能据此推断任意资料和任意查询的回答正确率。

**容易误判的细节：**“执行记录”正文没改，块 ID 仍然变化。当前块 ID 的哈希输入含资料版本、路径、行号和正文；任一文档替换导致整个场景的版本变化，所以所有块都会重新获得 ID。这保证请求记录可指向明确版本，但不能用块 ID 是否相同判断两个版本中的段落内容是否相同。若要做跨版本内容去重，需要另存独立的内容哈希。

本次两次回答均引用 `[1]`，且该块确实支持“次数”和“失败后停止并记录原因”这两个断言。引用编号有效只是自动检查，证据是否支持断言仍需人工核对。其余两块虽进入上下文，没有被答案引用；这也说明“进入上下文”和“被引用”是两个不同事件。

练习问题：如果只修改“失败重试”段落，为什么“执行记录”的块 ID 也变化？如果希望识别跨版本完全相同的段落，应增加什么标识？

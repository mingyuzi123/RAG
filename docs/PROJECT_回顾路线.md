# 从项目地基回顾 RAG

四阶段基础版已搭好，PDF 文本输入、页码引用和可检查的自动英文检索词也已接入。第一次从仓库启动时，先读[从零上手并学会这个 RAG 项目](从零上手并学会这个RAG项目.md)；下面按“先能解释链路，再能解释失败，最后能解释复用”的顺序回顾。每次选一题：先自己预测，再在页面核对候选、实际上下文、回答和引用。项目完成度与学习掌握度分开记录在 [PROGRESS.md](../PROGRESS.md)。

| 回顾单元 | 页面与案例 | 能独立回答的问题 |
| --- | --- | --- |
| 1. 资料到答案 | CrewAI C07；看原文行号、块 ID、Top 10、前 3、真实回答 | 一次问答经历哪些步骤？块 ID 为什么要绑定内容与版本？C07 为什么能答对却被旧章节指标标黄？ |
| 2. 检索策略与预算 | CrewAI C02、C04、C10；对比 BM25、E5、RRF、人工多查询 | 两路排名怎样融合？召回成功与进入上下文有什么差别？为什么不能一味增大 Top K 或上下文 K？ |
| 3. 答案与引用评测 | Pydantic P01、P06、P07、P09；查看人工审核 | 为什么章节命中既会高估也会低估答案质量？引用编号有效与断言被支持有何区别？ |
| 4. 可复用骨架 | 对照两个场景包的 manifest、ui 和 eval；分别打开 8767、8768 | 换场景改动了哪些配置？哪些核心代码共用？怎样证明两个场景的索引和请求没有混用？ |

完成这四单元后，再任选一题写半页实验记录：问题、预期证据、实际候选、实际上下文、回答/引用判断、可能改进、如何在新题验证。面试表达以这份真实记录为依据，不背孤立术语。更细的题目与参考回答见 [RAG 面试问答](RAG_面试问答.md)。

查询改写可用 [v1/v2/v3 逐题对照](../reports/QUERY_REWRITE_V3.md)练习：C14 已知题改善，C01 曾退步后恢复，P01 虽仍命中前 3 但名次下降。分别判断这三种变化能支持什么结论。

## 接下来的学习与项目落地

最近一次组合测试见[自动查询＋父块/邻块完整回答检查](../reports/QUERY_CONTEXT_COMBINED_AUDIT.md)。下一步学习练习：对照 P06 的两个实际上下文，找出补入的 after 证据、对应引用和字符预算；再解释为什么 9 题的上下文不变，以及为什么单独有效的两项优化仍需要组合验证。

每次只研究一个故障。开始前，先由学习者写出预期证据、可能出错的环节和只改一个变量的测试；再看页面、原文和请求记录。结束时用自己的话解释结果，并记录反例。一个案例讲通后换未参与设计的题验证，避免把针对已知题的修改当成通用改进。

| 单元 | 要学会解释 | 实际产出与验收 |
| --- | --- | --- |
| A. 完整链路 | 原文、解析、知识块、索引、候选、上下文、回答、引用和版本如何串起来 | 自己画链路，并用 P01 请求逐环标出证据和缺口；能区别事实正确与所给证据支持 |
| B. 检索与实验 | BM25、E5、RRF、人工多查询和自动英文查询分别改变什么；Recall@K 与 Context Hit@K 如何判断失败位置 | 固定题集、版本与预算，只改一个策略；复现[6 题查询试测](../reports/AUTO_QUERY_PILOT.md)的 C14 退步，再在未参与调参的题上复验 |
| C. 答案评测 | 章节标注、原文句子和答案断言为什么会不一致；怎样审查引用、局部拒答与无答案题 | 为一组题补充答案要点和可接受的原文范围，人工复核有争议的回答 |
| D. PDF 场景适配 | PDF 提取、页码/版面、标题、表格和引用定位会给现有切块器带来什么问题 | 文本型 PDF 入口和页码引用已实现；下一步导入真实许可 PDF，核对复杂版面与原页证据 |
| E. 项目交付 | 骨架怎样换资料、怎样复现评测、失败边界是什么 | 一键启动说明、固定演示题、实验报告、已知限制和简历中可验证的技术贡献 |

工程功能完成与学习掌握分开验收。A–C 的重点是能独立定位错误并设计验证；D–E 的重点是把同一方法迁移到新资料并让别人复现。目标邻块规则已作为页面可选实验接入；接下来的回顾先从 A 的 P01 开始，再用新题检查规则是否真的有收益。

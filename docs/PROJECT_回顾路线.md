# 从项目地基回顾 RAG

四阶段基础版已搭好，下面按“先能解释链路，再能解释失败，最后能解释复用”的顺序回顾。每次选一题：先自己预测，再在页面核对候选、实际上下文、回答和引用。项目完成度与学习掌握度分开记录在 [PROGRESS.md](../PROGRESS.md)。

| 回顾单元 | 页面与案例 | 能独立回答的问题 |
| --- | --- | --- |
| 1. 资料到答案 | CrewAI C07；看原文行号、块 ID、Top 10、前 3、真实回答 | 一次问答经历哪些步骤？块 ID 为什么要绑定内容与版本？C07 为什么能答对却被旧章节指标标黄？ |
| 2. 检索策略与预算 | CrewAI C02、C04、C10；对比 BM25、E5、RRF、人工多查询 | 两路排名怎样融合？召回成功与进入上下文有什么差别？为什么不能一味增大 Top K 或上下文 K？ |
| 3. 答案与引用评测 | Pydantic P01、P06、P07、P09；查看人工审核 | 为什么章节命中既会高估也会低估答案质量？引用编号有效与断言被支持有何区别？ |
| 4. 可复用骨架 | 对照两个场景包的 manifest、ui 和 eval；分别打开 8767、8768 | 换场景改动了哪些配置？哪些核心代码共用？怎样证明两个场景的索引和请求没有混用？ |

完成这四单元后，再任选一题写半页实验记录：问题、预期证据、实际候选、实际上下文、回答/引用判断、可能改进、如何在新题验证。面试表达以这份真实记录为依据，不背孤立术语。更细的题目与参考回答见 [RAG 面试问答](RAG_面试问答.md)。

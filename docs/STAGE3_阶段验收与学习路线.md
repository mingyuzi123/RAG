# 第 3 阶段：地基验收与回顾路线

更新于 2026-10-23。本阶段的目标是让一次技术文档问答可以从资料、知识块、候选、上下文一直追踪到回答，并用固定题集比较检索策略。下面的“完成”指功能和可复现实验已经落地，不表示答案质量达到生产要求。

## 地基包含什么

| 环节 | 已有实现 | 怎样核对 |
| --- | --- | --- |
| 固定资料 | CrewAI 官方文档提交、场景清单、19 道题及标注章节 | `python scripts/validate_crewai_eval.py` |
| 入库 | MDX 解析、标题/段落/表格切块；块 ID 绑定来源、版本和内容 | `python -m raglab index`，在检索结果中查看标题、行号和原文链接 |
| 召回 | BM25 英文词匹配、E5 中文到英文语义检索 | 页面“检索实验”并排比较候选排名 |
| 融合与上下文 | RRF 融合两路排名，候选前 10 取上下文前 3；人工多查询可选 | 看候选排名与“进入上下文”标记；实验报告保留逐题结果 |
| 生成与追踪 | DeepSeek 带出处回答、实际上下文与请求记录 | 页面“带出处问答”“请求记录”；对照原文人工核验 |
| 固定评测 | 同一 17 道可回答题、同一文档和 K 值的三路报告 | 页面“阶段评测”；红/黄/绿定位缺失环节 |

阶段评测目前只判定**标注章节是否出现**：候选前 10 是召回覆盖，上下文前 3 是送给模型的证据覆盖。绿色仍可能回答错误或误引；红色也可能存在未标注但可用的证据。因此逐题状态是诊断线索，不是正确率。固定报告还依赖同一资料提交、题集、证据标注和 K 值；页面会拒绝混用不一致的报告。

## 验收结果和取舍

- 当前表格切块索引下，BM25 为 **14/17、11/17**，E5 中文为 **13/17、10/17**，混合 RRF 为 **15/17、12/17**。数字依次表示标注证据全部进入候选前 10、上下文前 3。[逐题报告](../reports/README.md)保留实验条件与失败案例。
- 人工拆分比较题在 6 题中使上下文覆盖从混合检索的 **3/6** 到 **4/6**，但自动 DeepSeek 拆题在另一组 6 题只有 **1/6**；因此不把自动拆题设为默认策略。
- 多样性选块使原 17 题中的 C10 改善，另一组 6 题没有整体提升；也不设为默认策略。它证明“候选已找到”和“前 3 选对”是两个可分开优化的问题。
- C02、C18、C19 的少量真实问答已人工核验；样本太小，不能称为答案准确率。引用编号有效只证明引用了给过模型的块，不证明断言由块支持。
- 长代码块的真实 token 预算、更稳健的排序、自动跨语言查询和第二场景复用仍要继续验证。第二场景与成规模答案评测属于第 4 阶段。

## 我们接下来怎样回顾

以 4 个具体题目串起设计和面试知识点；每题先预测，再在页面查看证据，最后核对 [面试问答](RAG_面试问答.md) 与 [实验报告](../reports/README.md)。不要求背代码，重点是能说出输入、失败环节、证据和下一步实验。

1. **C02：切块和融合。**先预测一个参数表格为什么可能被段落切块破坏，再看 BM25、E5 和 RRF 的候选及前 3。回答“为什么两路都有排名可能胜过单路很高排名”。
2. **C10：候选与上下文。**在阶段评测中找黄色状态；核对 `@start()` 在候选中但不在原前 3。回答“Recall@10 上升时 Context Hit@3 为什么可能不变”，并解释一次多样性选块改善为何不足以上线。
3. **C04：多证据题。**对照 Agent 与 Task 的 tools 标注章节，判断原混合检索是候选缺失还是前 3 排错；再看人工子问题如何分别找两侧证据。回答“为什么把上下文 K 加大不保证更正确”。
4. **C18：拒答与引用。**打开真实请求记录，区分“所给摘录不足”和“整套文档不存在”。回答“引用编号合法为何不等于引用支持结论”。

回顾后自己完成一次小练习：选一题未讨论的 C07 或 C15，先写出预计失败环节与依据，再运行三路对比；如需改策略，先固定评测条件，并在未参与改动的新题或第二场景核验。学习进度以能够独立解释案例为准，不以看过页面为准。

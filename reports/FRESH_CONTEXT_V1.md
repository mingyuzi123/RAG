# 新题复验：目标邻块规则 v1

2026-11-05。测试题先于任何本轮运行结果提交，固定在 Git 提交 `307474d` 的 `scenarios/pydantic/eval/fresh_context_v1.jsonl`。文档仍为 Pydantic v2.13.2 固定提交；两组使用同样的中文问题、人工英文检索词、混合 RRF Top 10、回答上下文 K=3、DeepSeek 生成提示词。每题每策略各调用一次。原始回答、所选块、行号、调用用量见 [逐题记录](fresh-context-v1-answers.json)。

## 判读

| 题型 | 直接取前 3 | 条件合并＋目标邻块 |
| --- | ---: | ---: |
| 8 道可回答题，预期要点完整 | 8/8 | 8/8 |
| 2 道无答案题，限定在所给文档而拒答 | 2/2 | 2/2 |
| 全部 | **10/10** | **10/10** |

按冻结的要点人工逐题检查答案；无答案题检查有没有编造具体数字。引用编号 20/20 有效，但这不自动证明所有额外陈述的语义支持。N04、N09、N10 的最终块集合有变化；其余七题相同。N04 两组都找到 `Ordering of validators`；N09/N10 两组都合理拒答。**本轮没有净增题，也没有观察到退步**。不能把旧 35 题的 +4 直接推广到新问题。

这组题有明显天花板效应：直接取前 3 已全部答对，因此只能检查规则没有误伤这 10 题，无法检验它能否修复新的上下文缺口。题目虽在运行前冻结，仍由知道规则设计的人编写、取自同一套已研究过的文档，不能称为独立盲测。下一组题需要预先设定难度分层，包括跨块比较、两处证据相距较远、答案在候选前 10 但不在前 3、正确证据不在前 10、以及无答案题；在冻结前只用原文和问题分类，不能参考任一策略的排名。最好再加入新文档场景，避免只在同一 Pydantic 文档上验证。

## 成本边界

两策略 10 题的检索阶段平均耗时分别约 **21.4 ms**、**41.1 ms**；后者需要额外检索定义子块并选窗口。DeepSeek 输入 token 总数为 **11139**、**10452**，总 token 为 **15013**、**14116**。这是一次本机运行，不能作为稳定延迟或费用基准；字符预算也不是 token 预算。

更关键的产品缺口：这些题的英文关键词由人编写。真实用户只提中文问题时，若系统不能自动生成或绕开英文检索词，当前分数不代表端到端体验。另一个缺口是 PDF 资料尚未经过解析、页码引用和扫描件处理。这两项比继续微调邻块阈值更值得投入。

复现：`python scripts/evaluate_fresh_context.py`；脚本使用本地 `.env` 的 DeepSeek 密钥，已存在的题目与策略结果会跳过，避免重复调用。
